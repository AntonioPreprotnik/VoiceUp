# S6.10 — Can VoiceUp show the browser and the tab Claude is working in?

Date: 2026-11-05 · Status: needs-follow-up

## Decision
Bring the browser to the front, with the keyboard, when the first Claude in Chrome action of a command finishes. The setting `claude.showBrowser` is off by default. VoiceUp can't choose the tab, so a small helper extension is being tested for that, as a personal tool and not part of the friends release.

## Evidence

Claude's tab, tested with one test tab behind another. Brave's window title shows the real active tab.

| Action on Claude's background tab | Active tab afterwards | Notes |
| --- | --- | --- |
| Create a second tab | Not Claude's | |
| `navigate` | Not Claude's | Page still reports `visible` and focused |
| `computer` screenshot | Not Claude's | Captures the background tab anyway |
| `computer` left click | Not Claude's | |
| `window.focus()` in the page | Not Claude's | |

`document.visibilityState` and `document.hasFocus()` said `visible` and `true` throughout, even with another tab showing. Likely the extension's debugger connection causes this. Don't use them to test which tab is showing.

Raising the window with `showBrowser()`, from a child process of Vitest:

| Case | Result | Time |
| --- | --- | --- |
| A `cmd` window in front | Brave came to the front | 576 ms |
| Brave already in front, 9 more runs | Reported success | Median 595 ms, includes a 200 ms check |

To reproduce: `VOICEUP_TEST_SHOW_BROWSER=brave npx vitest run test/integration/show-browser.test.ts`.

In real use on 2026-11-05, with the packaged daily copy, a voice command and a real Claude session:

| Case | Result |
| --- | --- |
| Brave closed, 3 commands that called `mcp__claude-in-chrome__tabs_context_mcp` | Logged `Could not show the browser: brave isn't open`; Claude carried on |
| Brave open behind another app, Antonio named the Claude in Chrome tools | Logged `Showed the browser (brave)` about 2 s after the call; Antonio confirmed it |
| Claude ran `Start-Process brave.exe <url>` instead of a browser tool | Brave came up by itself; VoiceUp logged nothing, as designed |

Other findings:
- `navigator.brave` was present in the test tab, so Claude in Chrome was running in Brave.
- `tool_name` already reaches the state machine through the hook schema. Claude Code names these tools `mcp__claude-in-chrome__*`, as seen in a session outside VoiceUp.
- Claude in Chrome 1.0.105 names its tab group `Claude` or `Claude (MCP)`, per its bundled code.

## Not yet proven
- That Windows always allows the raise. It worked in the one real case, after a voice command, but one `AttachThreadInput` attempt failed in the first test and later plain calls worked, so the rule isn't understood. A refused raise logs `Windows did not let the browser come to the front`.
- The helper extension. Only a person can load it, in `brave://extensions`. It's in `spikes/S6.10/tab-follow/`.

## Environment
Windows 10 Home 19045, AMD Ryzen 5 3600, 16 GB RAM, Electron 45.2.1, Brave 156.1.98.63, Claude in Chrome 1.0.105.

## Consequences
- VoiceUp follows only Claude in Chrome tools. If Claude drives the browser with its own shell commands, as it did unprompted on 2026-11-05, nothing raises the browser beyond what those commands do themselves.
- S6.10 is added to E6 and built ahead of S6.2. TECH_SPEC §4.6 and §6.4 are updated.
- S6.8 still promises only Chrome and Edge. Claude Code's docs don't list Brave, and reports about it conflict, so Brave could stop working after an update.
- If a helper is kept, it needs its own story, including how it's installed.

## Rejected options
- **Raise when the command is sent:** VoiceUp can't know yet whether Claude will use the browser, so it would jump up for coding commands too.
- **Raise on `PreToolUse`:** a permission prompt for that action would open behind the browser, which also has the keyboard.
- **Raise without taking the keyboard:** Antonio asked for the keyboard to move too.
- **Brave's remote debugging port:** it can switch tabs, but lets any program on the PC control a signed-in browser.
- **Sending Ctrl+Tab or similar:** VoiceUp can't tell which tab it would land on.
- **A native addon for window calls:** one fixed PowerShell script does this at about 0.6 s, once per command, without another native module to verify on each Electron upgrade.
