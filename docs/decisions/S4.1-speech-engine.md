# S4.1 — Does `sherpa-onnx-node` work in packaged Electron, and which model is the default?

Date: 2026-11-03 · Status: needs-follow-up

## Decision

Use `sherpa-onnx-node` 2.0.0 in a `utilityProcess`, as designed, with **Moonshine base as the default model for everyone**. Antonio chose this over the planned RAM-based pick of Parakeet at 15 GiB or more. Parakeet stays available as a setting. The fallback to whisper.cpp isn't needed.

**Follow-up:** the benchmark on the weakest friend's laptop isn't done. Antonio deferred it, so it moved to S7.5, before the friends release.

## Evidence

Everything ran in a packaged `--dir` build with all five fuses set, with the engine in a `utilityProcess`. Model archives matched the size and SHA-256 in TECH_SPEC §5.4.

**The AC checks**

| Check | Result |
| --- | --- |
| Addon loads in the packaged `utilityProcess` | Yes; adds 23 MB unpacked |
| Silero VAD and recognition on live mic frames | Yes: 20 commands from a connected microphone, Parakeet, through a `MessagePort` from an AudioWorklet |
| `vad.front()`, `readWave(path)` | Throw `External buffers are not allowed` |
| `vad.front(false)`, `readWave(path, false)` | Work |
| VAD cost | About 206 µs per 32 ms frame |

The external-buffer rule has no automated test yet: `worker.js` records the behaviour above, but production code doesn't exist until S4.2, which should carry the check in its packaged smoke test.

**20 spoken commands, one speaker (Antonio), recorded through the live pipeline.** Median clip 2.4 s, longest 4.0 s. Command 1 is left out of the error rate: Antonio said something else by mistake, and all three models agreed on what they heard. Decode times include all 20. Run with `npm run bench:speech`, in Node, 4 threads.

| Model | Word errors, 19 clips | Median decode | Worst decode | Median RTF |
| --- | --- | --- | --- | --- |
| Moonshine base | 5.6% (7 of 125) | 108 ms | 155 ms | 0.045 |
| Whisper base.en | 5.6% (7 of 125) | 286 ms | 362 ms | 0.115 |
| Parakeet TDT 0.6B v2 int8 | 7.2% (9 of 125) | 240 ms | 345 ms | 0.101 |

The accuracy gap is two words in one voice, so it is not evidence that one model is more accurate. The speed gap is consistent. The packaged live run agrees with the Node numbers: Parakeet median 207 ms, worst 303 ms. End of speech to text is therefore the 1.2 s silence window plus about 0.1–0.3 s on this PC.

Moonshine's misses to know about: "git" as "get", "list" as "Liz", "stop" as "talk". S5.2's preview window is what protects against these.

**Memory and load, packaged, 6.6 s clip**

| Model | RSS with model loaded | Load | Decode |
| --- | --- | --- | --- |
| Moonshine base, alone, 3 runs | 387 MB | 1.5 s; 4.6 s on the first run | 287 ms |
| Parakeet, first in its process, 1 run | 837 MB | 2.9 s | 801 ms |
| Whisper base.en | Not measured alone | 0.9 s, after other models | 696 ms |

**Model archive extraction on Windows**

| Method | Result |
| --- | --- |
| `C:\Windows\System32\tar.exe -xjf` | **Deadlocks.** It has no built-in bzip2, spawned an external `bzip2 -d`, and both sat at 0 CPU for 20 minutes |
| Git's `tar -xjf` | Moonshine 73 s, Parakeet 158 s, Whisper 104 s |

A friend's PC may have no `bzip2` at all. S4.3 can't depend on the system `tar`, and needs a progress display.

**Reproduce.** `spikes/S4.1/`: `npm install`, `npx install-electron`, `npx electron-builder --win --dir --publish never`, then `S41Spike.exe --result=<file> --models=<folder>` for the benchmark, or `--record=<folder> --models=<folder>` for the live recorder. Then, in `desktop/`, `npm run bench:speech -- <recordings> <models>`. The recordings stay out of the repo.

## Environment

Windows 10 Home build 19045, AMD Ryzen 5 3600 (12 logical, 4 threads used), 15.9 GiB RAM. Node 24.21.0, Electron 45.2.1, electron-builder 26.18.1, `sherpa-onnx-node` 2.0.0. Whisper archive: `sherpa-onnx-whisper-base.en.tar.bz2`, 208,576,005 bytes, SHA-256 `475bc7052ce299c007f6d5d5407ba8601f819a2867f6eecee510ed17df581542`.

## Consequences

- **S4.2:** moves `sherpa-onnx-node` from a dev dependency to a dependency, uses the copying calls, and adds a VAD to the smoke test.
- **S4.3:** the first-run default is Moonshine (about 250 MB), with no RAM pick. It picks an extractor that doesn't need the system `tar`, and shows progress, because extraction takes over a minute.
- **S5.2:** the preview window stays important: Moonshine's misses change the meaning of a command.
- **S7.5:** runs `bench:speech` on the weakest friend's laptop before the friends release. If Moonshine is too slow there, or misses too much, revisit this note.
- **TECH_SPEC:** §1 targets, §5.3, §5.4, §6.4 and §11 updated. `settings.ts`: `auto` now resolves to Moonshine.

## Rejected options

- **RAM-based pick (Parakeet at 15 GiB or more):** on this voice it wasn't more accurate, while being about twice as slow, using over twice the memory, and needing a 482 MB download. One default is also one thing to support.
- **Whisper base.en:** matched Moonshine's accuracy here at under half the speed, with nothing to offset it.
- **whisper.cpp `whisper-server` with `vad-web`:** the fallback for the addon failing in Electron, which it didn't.
